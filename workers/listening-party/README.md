# сервер комнат seWer

## публикация в уже созданный worker

1. в cloudflare открой `sewer-party` → **edit code**.
2. замени весь основной файл содержимым `workers/listening-party/index.js`.
3. нажми **deploy**. имя класса `MyDurableObject` и binding `MY_DURABLE_OBJECT` сохранены из твоего шаблона. новые bindings, миграции и секреты не нужны.
4. открой `https://sewer-party.dysphorialkxd.workers.dev/health`.
5. ожидаемый ответ: `{"ok":true,"service":"sewer-party","protocol":1}`.

при следующих деплоях из github обновляй исходный `src/index.ts` в серверном репозитории: ручное изменение через **edit code** не меняет github. конфигурацию durable objects оставь прежней.

frontend подключён к этому адресу через `src/party-client.js`. кнопка комнаты только показывает и скрывает её, не разрывая соединение. для создания и входа нужен собственный soundcloud-доступ; локальные файлы в комнате не воспроизводятся.

ведущий выбирает один общий трек и управляет воспроизведением. гость загружает его через свой soundcloud, следует за паузой и перемоткой; недоступный трек или запрет автозапуска показываются с кнопкой повторной попытки. громкость, эквалайзер и стерео остаются личными. скорость фиксируется на 1×, тон на 0, кроссфейд и автоматический переход отключены только на время комнаты, сохранённые настройки не меняются. у ведущего ручной выход сохраняет обычное воспроизведение, у гостя ставит его на паузу.

после обрыва связи музыка ставится на паузу, клиент до 45 секунд пробует прежний токен без повторного входа. токены живут только в памяти и не сохраняются после перезапуска приложения. работа звука двух реальных soundcloud-клиентов требует ручной проверки в приложении; модульные тесты проверяют протокол, декодерные состояния, отмену загрузок и переподключения.

при явном выходе клиент ждёт подтверждение закрытия до 2,5 секунд, затем освобождает соединение. если подтверждение не пришло, интерфейс предупреждает, что комната может оставаться открытой.

## проверка в приложении

1. у обоих слушателей войди в soundcloud. у ведущего выбери доступный трек, открой комнаты и создай комнату.
2. скопируй код и введи его на втором устройстве. проверь обоих участников, одинаковый трек, паузу, продолжение и перемотку ведущим.
3. выбери другой трек у ведущего. у гостя кнопки транспорта не должны менять общий звук. эквалайзер, стерео и громкость проверь отдельно у каждого.
4. несколько раз быстро скрой и открой комнату: соединение и звук не должны переключаться. отключи сеть у ведущего, проверь паузу и переподключение без самопроизвольного запуска.
5. закрой комнату ведущим, проверь возврат гостя в начальный экран и восстановление личных настроек скорости/тона. отдельно проверь недоступный трек и повторную попытку.

## протокол v1

- `POST /v1/rooms`, JSON `{profile:{name,avatarUrl},track}`: создать комнату. трек может быть `null` или `{source:"soundcloud",id,title,artist,coverUrl,duration}`. длительность и позиции в секундах.
- `POST /v1/rooms/ABC234/join`, JSON `{profile:{name,avatarUrl}}`: войти по коду. ответ создания/входа: `{protocol,code,memberId,token,role}`. `token` хранить только локально, не копировать в приглашение и не писать в логи.
- websocket: `wss://sewer-party.dysphorialkxd.workers.dev/v1/rooms/ABC234/socket` с subprotocols `["sewer-party.v1", "token." + token]`. токен не передаётся через query string. сервер выбирает протокол `sewer-party.v1`.
- сервер присылает `room`: `{protocol,code,you:{id,role},members,track,playback:{playing,position,updatedAt,revision},serverTime}`. `members` содержит подключённых участников, не примеры. имена и аватары самозаявленные, не проверенные аккаунты soundcloud.
- ведущий: `{type:"track",track}` заменяет единственный трек и ставит его на паузу с позиции 0. `{type:"playback",playing,position}` публикует состояние настоящего декодера. скорость фиксированная 1; общих EQ, стерео, эффектов и очереди нет.
- любой участник: `{type:"ping",nonce}` → `pong` с `serverTime`; `{type:"leave"}` выходит, а для ведущего закрывает комнату всем.
- серверные ошибки: `error` с машинным кодом; окончательное закрытие: `closed` с `reason`.

## ограничения

- максимум 8 участников; комната живёт не дольше 6 часов.
- гость может переподключиться с прежним токеном в течение 60 секунд после отключения; ведущий до истечения комнаты. новая связь с тем же токеном заменяет старую.
- при отключении ведущего сервер ставит трек на паузу. переподключение само по себе не запускает музыку.
- лимиты на IP: 3 создания, 20 входов, 40 websocket-подключений в минуту; 20 сообщений в секунду на соединение. HTTP и websocket JSON ограничены 4 KiB.
- допустимые browser origins: `http(s)://tauri.localhost`, localhost/127.0.0.1 на 1420 и 5173. запросы без origin допустимы для native клиентов. CORS не является аутентификацией.
- worker передаёт только метаданные и состояние. soundcloud каждый плеер воспроизводит самостоятельно с собственным доступом. сервер никогда не принимает stream URL, локальные файлы или soundcloud-токены.
- используются hibernating websockets и storage. пауза не создаёт непрерывный серверный таймер. ограничения уменьшают злоупотребления, но не заменяют account-level лимиты расходов в cloudflare.
